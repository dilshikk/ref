# Реферальный бот

Telegram-бот (aiogram 3 + PostgreSQL): пользователи приглашают друзей в группу по
персональной ссылке и получают деньги за каждого вступившего, затем выводят их на
карту или телефон. Администраторы проверяют выплаты, управляют тарифами,
каналами обязательной подписки и рассылками.

## Запуск в Docker

```bash
cp .env.example .env       # токен, админы, PostgreSQL, ключ шифрования реквизитов
docker compose up -d --build
docker compose logs -f bot
```

Затем в боте откройте `/admin` и задайте:

1. «📢 Каналы и группы» → «👥 Группа приглашений» → «🆔 ID группы» — группа для
   реферальных ссылок (бот должен быть в ней администратором). Пока она не задана,
   бот при старте напоминает об этом админам, а реферальные ссылки и вывод отвечают
   понятным сообщением.
2. «👥 Пользователи» → «👑 Администраторы» — кто из админов одобряет выплаты (денежные админы).
3. «⚙️ Настройки» → «💸 Выплаты» и «🎁 Награды» — суммы вывода и награды.
4. «📢 Каналы и группы» → «📌 Обязательные подписки» — обязательные каналы.

Необязательно: «📢 Каналы и группы» → «📝 Группа логов»;
«⚙️ Настройки» → «🆔 Чат выплат», «📝 Тексты», «🗳 Опрос», «🛡 Антифрод».

## Меню админа

Каждая настройка находится ровно в одном месте (это проверяют тесты).

| Раздел | Что внутри |
|---|---|
| 📊 Статистика | Только просмотр: новые пользователи, активность, рефералы (с топом), финансы, каналы, периоды |
| 💰 Финансы | Заявки на выплаты, на удержании, балансы, бонусы, отчёты |
| 👥 Пользователи | Поиск, список, изменить баланс, сообщение, заблокированные, администраторы и денежные админы |
| 📢 Каналы и группы | Обязательные подписки, группа приглашений (ссылка и ID), группа логов |
| 📨 Рассылки | Новая, история, запланированные, статистика рассылок |
| ⚙️ Настройки | Выплаты, награды, антифрод, чат выплат, тексты, опрос, команды меню |
| 📋 Логи | Журналы по категориям |

«⬅️ Назад» возвращает в главное меню, «⬅️ К каналам» и «⬅️ К настройкам» во
вложенных меню — на шаг вверх.

## Запуск без Docker

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

## Настройки

- `.env` — только то, без чего бот не запустится: `BOT_TOKEN`, `ADMINS`, `DB_*`
  и `PAYOUT_ENCRYPTION_KEY` (ключ не хранится в базе рядом с зашифрованными картами).
  `ALLOW_PLAINTEXT_PAYOUTS=1` — аварийный флаг, только осознанно.
- Всё остальное хранится в базе (таблица `bot_settings`) и меняется в админ-панели
  без перезапуска. Каждое изменение видно в «📋 Логи» → «⚙️ Изменения».
  В коде настройки читаются только через `data/settings.py: get_settings()` —
  мусорные значения заменяются значениями по умолчанию.

## Переезд со старой версии

Ничего переносить вручную не нужно. При первом запуске новой версии бот сам:

- переносит `config/url.yml` (или `data/url.yml`, или путь из `URL_YML_PATH`) в базу —
  только если в базе ещё нет настроек;
- добавляет каналы из `url.yml` в список обязательных подписок;
- переносит `GROUP_ID`, `LOG_GROUP_ID`, `MONEY_ADMIN`, `MONEY_ADMINS` из `.env` —
  только те, которых ещё нет в базе.

Перенос записывается в журнал (`settings_migrated`), повторный запуск ничего не меняет.
После первого успешного запуска старые переменные из `.env` и файл `url.yml`
(вместе с директорией `config/` и строкой `./config:/app/config` в своём
`docker-compose.yml`) можно удалить.

## Проверки и тесты

```bash
pip install -r requirements-dev.txt
ruff check .
python -m pytest tests -q
```

То же самое запускается на GitHub при каждом push и pull request
(`.github/workflows/ci.yml`).

## Структура

| Папка | Что внутри |
|---|---|
| `handlers/` | Обработчики: `private/` — личка и админка, `groups/` — вступления и выходы из группы |
| `middlewares/` | Блокировка, обязательная подписка, антиспам, журнал действий |
| `services/` | Подписка, рассылки, проверка добавленных участников, аудит, хранение настроек |
| `utils/` | Чистая логика (деньги, капча, реквизиты, подписка) и работа с БД (`utils/db/`) |
| `data/` | `.env` (`config.py`) и чтение настроек из базы (`settings.py`) |
| `tests/` | Тесты на pytest |
